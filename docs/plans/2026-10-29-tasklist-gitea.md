# Kanban WebUI → тасклист и лог выполнения

**Цель:** два новых вида рядом с доской — список задач и журнал выполнения. Схема не меняется,
git не подключается, сроки не вводятся.

**Решения владельца (29.10.2026):**

1. Отдельный список задач, фильтр по исполнителям и статусам.
2. Лог выполнения — отдельно.
3. Gitea не нужен.
4. Срок не нужен.
5. Вложения — уточнить (объяснено ниже: это файлы, и они уже есть).

**Следствие:** ни одного нового поля, ни одной миграции. Всё строится на существующих
`task_runs` (59 строк), `task_events` (879), `task_attachments` (26 файлов, 880 КБ).

## Что уже есть в данных

`task_runs`: `id, task_id, profile, step_key, status, claim_lock, claim_expires, worker_pid,
max_runtime_seconds, last_heartbeat_at, started_at, ended_at, outcome, summary, metadata, error`

- исходы: `completed 38`, `scheduled 9`, `blocked 5`, `reclaimed 5`, `crashed 2`
- исполнители: `coder 20`, `hermes 12`, `dispatcher 8`, `default 4`, `homelab 4`, `reviewer 1`, пусто 10
- прогоны **никогда не удаляются** — история постоянная

`task_events`: 879 строк, из них `heartbeat` — 344 (шум, в логе скрывать), дальше `created`,
`commented`, `edited`, `completed`, `worker_bound`, `spawned`, `claimed`, `worker_result`, `attached`.
GC чистит события только у `done`/`archived` и только по явному `hermes kanban gc` — история живая.

**Важное ограничение Hermes:** `list_events(conn, task_id)` и `list_runs(conn, task_id)` — только
по одной задаче. Глобальных выборок нет, поэтому оба вида читают базу прямым `SELECT`
(чтение разрешено, запись — только через `kanban_db`).

## P1. Вид «Список» (3 ч)

Навигация в шапке: **Доска · Список · Лог**.

Таблица, одна строка — задача:

| статус | исполнитель | приоритет | заголовок | тенант | создана | прогонов | комментариев |

- Фильтры: **исполнитель** (мультивыбор), **статус** (мультивыбор), поиск по тексту, архив вкл/выкл.
- Сортировка по любому столбцу, по умолчанию — свежие сверху.
- Клик по строке открывает тот же drawer, что и на доске.
- Данные: `/api/board` уже отдаёт `columns` + `tasks`; для списка нужен
  `GET /api/list?assignee=&status=&q=&archived=` — плоский массив с теми же полями плюс
  `run_count` и `comment_count`.
- Фильтр по статусу появится и в тулбаре доски — сейчас его нет, хотя статусы в данных есть.

**Файлы:** `kanban_webui/kanban_api.py` (эндпоинт), `static/list.js` (новый),
`static/index.html` (секция + навигация), `static/app.js` (переключение видов),
`static/i18n.js` (подписи), `static/style.css` (таблица), `tests/test_list_view.py`.

## P2. Вид «Лог» (3 ч)

Отдельная страница — журнал выполнения, новые сверху:

```
14:02  coder     homelab · «Бэкенд: pulsevibeapi основной»      12м 14с   завершено
        Портал переведён на двух провайдеров, баланс и затраты…
14:15  homelab   «Утечка ключа forgetapi…»                      31м 32с   заблокировано
        Локальная зачистка завершена, ждёт решения по ротации
```

- Одна строка = один прогон: время старта, профиль, задача, длительность, исход.
- Раскрытие строки: `summary`, `error`, метаданные (токены/сессия), ссылка на карточку.
- Фильтры: исполнитель, исход, конкретная задача, период (сегодня / 7 дней / всё).
- Вторая вкладка внутри лога — **события** (created/claimed/completed/commented), `heartbeat`
  выключен по умолчанию: их 344 из 879.
- `GET /api/log?limit=50&before=&assignee=&outcome=&task=&since=` — постранично, курсором.

**Файлы:** `kanban_webui/log_view.py` (новый, чистые функции + SQL),
`static/log.js` (новый), `kanban_api.py` (эндпоинт), `tests/test_log_view.py`.

## P3. Вложения (1.5 ч)

Это **файлы, приложенные к карточке**. Hermes их складывает сам: когда воркер завершает задачу
через `kanban_complete`, его артефакты попадают в `~/.hermes/kanban/attachments/<task_id>/`
и в таблицу `task_attachments`.

Уже есть 26 штук, 880 КБ:

```
CLEANUP_REPORT.md                     отчёт по зачистке ключа
VERIFICATION.md                       проверка провайдеров
hermes-agent-provider_media.patch     патч
image_gen_routerai_seedream-5-0-flash.png
stt_input_sample.mp3
```

Сейчас доска их не показывает — результат работы воркера виден только текстом в summary.
Предлагаю: список вложений в drawer с размером и типом, скачивание через
`GET /api/tasks/{id}/attachments/{name}` с проверкой, что путь внутри
`~/.hermes/kanban/attachments` (никаких `../`), и счётчик вложений в строке лога.

**Файлы:** `kanban_api.py` (два эндпоинта), `static/drawer.js`, `tests/test_attachments.py`.

   `scripts/probe-layout.py` на 390/1280/1440/1920 — перехлёста нет; на телефоне таблица

2. **P2** — лог. Проверка: эндпоинт отдаёт ровно 59 прогонов без дублей, пагинация не теряет

3. **P3** — вложения. Проверка: путь вне каталога вложений → 403; скачивание 26 файлов совпадает
   по размеру с базой.

Каждый этап — отдельный коммит, тесты перед коммитом, снимок экрана после UI-этапа.

## Риски

1. **Дублирование с доской.** Список и доска показывают одни данные; если список не даст того,
   чего не даёт доска (сортировка, плотность, фильтр по статусу), он станет вторым способом
   делать то же самое. Смысл появляется только с фильтрами и сортировкой — их и делаем первыми.
2. **Лог на 59 прогонах выглядит пусто**, пока агенты мало работают. Не баг, но первые
   впечатления будут скромными.
3. **Прямой SELECT в обход `kanban_db`.** Чтение разрешено, но при изменении схемы Hermes
   (переименование колонки) сломается молча — поэтому все запросы в одном модуле `log_view.py`
   и покрыты тестами на реальной схеме.
4. **Мобильный вид.** Таблица на 390 px превращается в кашу; нужен отдельный рендер списком
   карточек.
