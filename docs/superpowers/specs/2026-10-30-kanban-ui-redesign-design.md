# KanbanWebUI: переработка интерфейса — «пульт, доска, лента»

Дата: 2026-10-30 · Статус: согласовано с владельцем в чате, к реализации
Проект: `hermes-kanban-webui` (форк `PriuS2/HermesKanban`, vanilla JS без сборки)
Макеты направлений: `~/.hermes/cache/scratch/kanban-mockups/{a-board,b-pult,c-feed}.html` (временные, 390px)

## 1. Зачем

Нынешний интерфейс читается как «сделано ИИ»: градиентный фон, `backdrop-filter: blur(18px)` на всех
панелях, радиусы 24px, кнопки-пилюли `999px`, эмодзи в контролах, Inter с Google Fonts, полоса из семи
KPI-плиток, дублирующая счётчики колонок. Плюс провалы юзабилити:

- колонка с 41 задачей уезжает за правый край, а три пустые колонки держат по 260px в центре экрана;
- карточка печатает сырой markdown (`##`, `**`, `<|--`) и микрометаданные 10–11px цветом ниже AA;
- id переносится на две строки, предупреждение об отсутствии профиля показано дважды;
- `ready` = «Готовы» и `done` = «Готово» — разные статусы почти одним словом;
- у каждой карточки висят неподписанные кружки-порты зависимостей;
- нулевые счётчики (`💬 0`, `↑0 ↓0`) занимают место.

## 2. Кто и как пользуется

Основной сценарий — **телефон**, наблюдение за прогонами агентов. Десктоп вторичен: планирование и разбор.
Типичное состояние базы — 42 `done`, 13 `archived`, ноль живых прогонов. «Пусто» — нормальное состояние,
а не аварийное, поэтому экран «Сейчас» обязан быть осмысленным при нуле живых прогонов.

## 3. Ограничения

- **Серверный API не меняется.** Только существующие эндпоинты (`/api/board`, `/api/list`, `/api/log`,
  `/api/log/events`, `/api/pulse`, `/api/ops/summary`, `/api/tasks/{id}`, `/api/events`). Агрегация — на клиенте.
  Если без серверного изменения не обойтись — остановиться и согласовать.
- **Без сборки и без новых зависимостей.** Никаких npm, CDN, шрифтов с внешних хостов.
- **Тёмная тема — основная.** Светлая собирается из тех же токенов (переопределение `:root[data-theme="light"]`),
  не отдельной вёрсткой.
- Совместимость с upstream-форком не требуется; ветка живёт своей жизнью.
- Сохраняются существующие id контролов (`boardSelect`, `taskCreateBtn`, `refreshBtn`, `newBoardBtn`,
  `themeToggle`, `langToggle`, `opsToggleBtn`, `workflowBtn`, `bulkBtn`) и контракты селекторов, на которые
  уже опираются `dependency-lines.js` (`.board-column`, `.task-card`, `.dependency-port`,
  `[data-task-id]`, `[data-parent-count]`, `[data-child-count]`) и `dragdrop.js`.
- Поведение операций (`/api/tasks/*`, связи, вложения, workflow) не меняется.

## 4. Экраны

### 4.1 «Сейчас» (главный экран телефона)

Четыре блока в фиксированном порядке:

1. **Живые прогоны** — по `api.board` (задачи со статусом `running`) + `api.pulse` (батч: `elapsed_sec`,
   `heartbeat_age_sec`, `overdue`, `profile`). Строка: заголовок → `27:14 / 60 мин` → `пульс 24 с` → `@coder`
   → полоса прогресса → действия `Лог`, `Карточка`. `overdue` (>300 с) помечается словом «пульс просрочен»
   и цветом — не только цветом.
2. **Требует внимания** — `blocked`; задачи без исполнителя в `scheduled|todo|triage|ready`; прогоны с
   просроченным пульсом. У каждой строки одно главное действие.
3. **Очередь** — `scheduled|todo|ready|triage`, сортировка по `priority` убыв., затем по возрасту.
4. **Завершено** — последние прогоны за 24 ч (`api.log`, `outcome=completed`) + сводка «N прогонов, M ошибок,
   средн. X мин» (считается на клиенте).

**Состояние простоя:** при нуле живых прогонов блок 1 не исчезает, а пишет «нет активных прогонов ·
последний завершился 25 ч назад», и экран показывает очередь и завершённые. Пустого экрана не бывает.
**Состояние ошибки:** при сетевой ошибке или 401 — строка «не удалось загрузить · повторить», не пустота.

Кнопки «Остановить» нет: остановка воркера — это `block` с причиной, поведение не меняем.

### 4.2 «Доска»

Телефон (<760px): секции по статусам вертикально, sticky-заголовок секции со счётчиком и `＋`; пустые
статусы схлопнуты в один ряд чипов внизу (тап — скролл к секции / разворачивание).

Десктоп (≥760px): колонки 320px, sticky-шапка, пустая колонка — рейл 40px с вертикальной подписью и
числом, тень-подсказка при горизонтальном скролле, автоскролл к первой значимой колонке
(`running` → `blocked` → `ready`), кнопка «к активной».

Режим «Таблица» (существующий вид «Список») переключается внутри вкладки «Доска», отдельной вкладкой не
становится.

Карточка задачи: одно предупреждение, id не переносится, метаданные в одну строку, нулевые счётчики не
рисуются, у `running` — строка пульса и полоса прогресса, markdown в карточке не печатается (только
заголовок + превью текста без разметки). Порты зависимостей видны только у выбранной карточки или в режиме
связывания.

### 4.3 «Лента»

Поток из `api.logEvents` + задачи, группировка по дням, сводка дня. Чипы-фильтры: `Требует меня` (дефолт) /
`Всё` / `Блокировки`. Инлайн-действия только там, где от пользователя реально чего-то ждут. Курсорная
пагинация — как в `log_view.py`.

### 4.4 «Лог»

Смысл сохраняется (прогоны / события, курсорная пагинация, режимы), но приводится к общим токенам:
одна строка фильтров вместо панели-карточки, моно-таймстемпы, плотные строки.

### 4.5 Карточка задачи (drawer)

Порядок: состояние и исполнитель → заголовок → отрендеренный markdown → действия → зависимости →
комментарии → вложения → прогоны и события. На телефоне — полноэкранный лист. Адрес карточки —
`#task=<id>`, ссылка открывается сразу в drawer.

### 5.3 Правила «анти-AI» (проверяются тестом)

Запрещено: линейные/радиальные градиенты в фоне; `backdrop-filter`; радиусы > 8px у карточек и > 999px у
кнопок (кнопки — 5px); эмодзи в подписях контролов и в тексте интерфейса; шрифты и иконки с внешних хостов;
декоративные тени у панелей; дублирование одного и того же счётчика в двух местах экрана.

## 8. Тесты и приёмка

- `pytest` — весь набор зелёный. `tests/test_static_smoke.py` переписывается: вместо ассертов точных строк
  CSS — контракты (наличие вью, ключей i18n, токенов, запретов из 5.3, отсутствие внешних шрифтов).
- Скриншот-пробы на 390 и 1440 (`scripts/`): нет горизонтального переполнения, вкладки переключают вью,
  `#view=now` открывается, `#task=<id>` открывает drawer.
- Живая проверка на телефоне через HTTPS-домен развёртывания (secure context обязателен для PWA и push).
- Статика отдаётся с диска — перезапуск сервиса не требуется; токен `?v=` в `index.html` поднимается один раз
  на задачу, все импорты обязаны использовать один и тот же токен (тест это проверяет).

## 9. Вне рамок

Operations-панель, массовое создание, AI workflow designer — не переделываются, только прячутся в «Ещё» и
получают общие токены. Мультидосковость, права, уведомления, серверные агрегаты — не здесь.

## 10. PWA (этап 2, после переработки UI)

Цель: установка на домашний экран Android/iOS, standalone-режим, офлайн-оболочка и фундамент под web-push.
HTTPS на домене развёртывания (Let's Encrypt) — обязательное условие для PWA и push.

- `static/manifest.webmanifest`: `name` «Hermes Kanban», `short_name` «Kanban», `start_url` `/#view=now`,
  `scope` `/`, `display` `standalone`, `background_color` `#0b0c0e`, `theme_color` `#0b0c0e`, `lang` `ru`,
  иконки 192/512 + 512 `maskable`. `orientation` не фиксировать.
- `static/icons/`: `icon-192.png`, `icon-512.png`, `icon-maskable-512.png`, `apple-touch-icon-180.png` —
  генерируются из одного SVG-знака скриптом `scripts/make_icons.py` через headless Chrome
  (`--default-background-color=00000000`, прозрачный фон).
- `static/sw.js`: precache оболочки с текущим токеном `?v=`; `network-first` для `/api/*` с фолбэком в кэш
  и ответом `503 {"offline": true}`; `cache-first` для `/static/*`; имя кэша = токен версии, старые кэши
  удаляются на `activate`; `skipWaiting` только по сообщению со страницы. Обработчики `push` и
  `notificationclick` (открывают `/#task=<id>`) присутствуют, но на этом этапе пушей никто не отправляет.
- `kanban_webui/app.py`: два маршрута **до** SPA-fallback — `GET /sw.js` (`application/javascript`,
  `Cache-Control: no-cache`, `Service-Worker-Allowed: /`) и `GET /manifest.webmanifest`
  (`application/manifest+json`). Сейчас оба пути отдают `index.html` с `text/html`, из-за чего браузер
  отказывается регистрировать service worker.
- `index.html`: `<link rel="manifest">`, `<meta name="theme-color" content="#0b0c0e">`,
  `apple-mobile-web-app-capable`, `apple-mobile-web-app-status-bar-style` `black-translucent`,
  `apple-touch-icon`; кнопка «Установить» по событию `beforeinstallprompt`; на iOS — одноразовая подсказка
  «Поделиться → На экран „Домой“» (флаг в `localStorage`).
- Обновление статики: существующий `update.js` показывает баннер «доступно обновление» при новом
  service worker (`controllerchange`), иначе телефон залипнет на старом интерфейсе.
- Приёмка: манифест — валидный JSON со всеми обязательными полями; SW регистрируется в headless Chrome;
  после `Network.emulateNetworkConditions offline` + reload страница отдаёт оболочку, а блоки данных
  показывают состояние «нет сети · Повторить».

### 10.1 Web-push (этап 3, отдельное решение)

Технически возможно на Android/Chrome (Pixel 8 — да) и на iOS ≥16.4 при установке на домашний экран.
Требует серверной части: VAPID-ключи (приватный — в env-файл), таблица подписок в
`~/.hermes/kanban-webui/` (не в `kanban.db`), отправка через `pywebpush` (+11 транзитивных пакетов,
проверено `uv pip install --dry-run`), фоновый отправитель на systemd-таймере, читающий `task_events.id`
после курсора. События для отправки: прогон стартовал, прогон завершился, задача заблокирована,
пульс просрочен (>300 с). Без согласования не реализуется.

### 10.2 Web-push: контракт реализации

Единственная новая зависимость проекта: `pywebpush` (+`cryptography`, `requests`, `http-ece`, `py-vapid`).

- **VAPID:** пара генерируется один раз скриптом `scripts/make_vapid.py` в
  `~/.hermes/kanban-webui/vapid-private.pem` (chmod 600). Публичный ключ отдаётся странице, приватный
  не покидает сервер и не попадает в git.
- **Хранилище подписок:** SQLite `~/.hermes/kanban-webui/push.db`, таблица
  `subscriptions(id INTEGER PRIMARY KEY, endpoint TEXT UNIQUE, p256dh TEXT, auth TEXT, ua TEXT, created_at INTEGER)`.
  `kanban.db` не трогать — он общий с CLI и диспетчером.
- **Маршруты** — новый модуль `kanban_webui/push_view.py`, подключается в `app.py`:
  `GET /api/push/key` → `{"public_key": "<base64url>"}`;
  `POST /api/push/subscribe` `{endpoint, keys:{p256dh, auth}, ua}` → 201, upsert по `endpoint`;
  `DELETE /api/push/subscribe` `{endpoint}` → 204.
- **Отправитель:** `scripts/push_notifier.py` + `deploy/systemd/hermes-kanban-push.{service,timer}`,
  `OnUnitActiveSec=30s`. Курсор в `~/.hermes/kanban-webui/push-cursor.json` (`{"last_event_id": N}`),
  читает `task_events` с `id > last_event_id`.
- **События для пуша (только эти):** `completed`, `worker_result` с `exit_code != 0`, `crashed`,
  `timed_out`, `blocked`. Никогда: `heartbeat` (575 записей из 1300 — чистый шум), `created`, `edited`,
  `promoted`, `dependency_wait`, `attached`.
- **Пейлоад:** `{title:"Kanban", body:"Прогон завершён · t_4f464521 · 30 мин", tag:"task:t_4f464521",
  task_id:"t_4f464521", url:"/#task=t_4f464521"}`. Заголовок задачи в текст уведомления **не попадает**
  по умолчанию — он виден на локскрине; включается `PUSH_INCLUDE_TITLE=true`.
- **Мёртвые подписки:** `410 Gone` / `404` от FCM → запись удаляется из базы.
- **Клиент:** кнопка «Включить уведомления» в панели «Ещё», подписка только по жесту пользователя;
  состояние показывается явно — «включены» / «запрещены в браузере» / «не поддерживается».
- **Приёмка:** подписка появляется в `push.db`; `scripts/push_notifier.py --dry-run` печатает пейлоад
  для каждого нового события; реальная доставка проверяется на Pixel 8 вручную (в отчёте — время отправки
  и время прихода).
